## 0. 이 문서가 PLAN을 바꾸는 지점 (Architecture Pivot)

PLAN.md의 1차안은 **포즈 추정을 Python 사이드카**(MediaPipe child process, stdio JSON)로 분리했고,
M0 스파이크에서 그 왕복을 검증했다. 본 설계서는 그 결정을 **뒤집는다**:

| 항목 | PLAN 1차안 / M0 | **본 설계서 (확정)** |
|---|---|---|
| 포즈 추정 위치 | Python 사이드카 (외부 프로세스) | **WebView2 내부 WASM** (MediaPipe Tasks `PoseLandmarker`) |
| 프레임 IPC | 웹캠 프레임을 Go로 전송 | **없음.** 프레임은 WebView 밖으로 나가지 않음 |
| Go ↔ JS 통신 | 프레임/랜드마크 데이터 | **성공 이벤트만** (몇십 바이트) |
| Python 의존성 | 필수 (런타임 번들) | **제거** |

**근거**: 1280×720 프레임을 base64로 직렬화해 Wails IPC로 Go에 넘기면 마샬링/언마샬링 비용이
프레임당 수백 ms 단위로 누적되어 실시간성을 파괴한다(추론 자체는 ~30ms). 모든 추론을 WebView2가
하드웨어 가속으로 직접 처리하면 IPC 오버헤드가 사실상 0에 수렴한다. 따라서 **Go는 비전 파이프라인에서
완전히 빠지고**, 학습 누적 기록 같은 시스템 작업만 담당한다.

> **M0 사이드카는 폐기(superseded)된다.** `app/sidecar/`, `app/sidecar.go`, `app/sidecar_test.go`는
> 본 설계 채택 시 제거 대상이다. M0의 가치는 "Wails 빌드 체인이 동작함"을 입증한 것으로 한정된다.

## 2. AI Hub 데이터셋 (기준 템플릿 생성용 · 개발 단계 한정)

> 모델을 직접 학습하지 않는다. AI Hub 데이터는 **표준 정자세/오류 기준 벡터를 추출**하는 용도로만 사용한다.

| 데이터셋 | 운동 | 규모(원천) | 라벨 |
|---|---|---|---|
| 피트니스 자세 이미지 | 스쿼트·풀업·푸시업 등 ~30종, 5뷰 멀티뷰 | **약 200만 장 (2D)** ※ | COCO-17 키포인트, 정자세/오류 분류 |
| 크로스핏 동작 | 동작 교정용 다채널 영상 | 원천 비디오 ~4,000클립 / 라벨 ~32,400 | 2D/3D 키포인트(CSV) + 동작 메타(JSON) |
| 스포츠 사람 동작(농구/골프) | 슈팅·스윙 등 고역학 동작 | ~200시간 / 432만 장+ | YOLOv4 바운딩박스 + PCK 관절(JSON) |

> ※ 원문의 "200,000만 클립"(=20억)은 명백한 오기로 판단. PLAN.md의 "2D 200만 장"과 일치시켜 **약 200만 장**으로 기재.
> 실제 규모/라이선스는 **AI Hub 다운로드 시 재확인 필요**(PLAN §2.3 리스크).

**핵심 구조적 가치**: 피트니스 데이터는 동작마다 **5개 전이 상태(Phase)** —
`시작 → 하강 → 최대수축 → 상승 → 종료` — 를 라벨링한다. 이를 **상태 기계(State Machine)**로 처리한다.

## 3. 웹캠 처리 아키텍처 (WebView2 제약 극복)

### 3.1 보안 컨텍스트 — `getUserMedia` 활성화

`navigator.mediaDevices.getUserMedia`는 **보안 컨텍스트**(HTTPS / localhost / file)에서만 동작한다.
로컬 HTTP로 자산을 서빙하면 비보안으로 간주되어 카메라 권한이 자동 거절된다.

**해법**: WebView2의 `CoreWebView2.SetVirtualHostNameToFolderMapping`으로 로컬 폴더를
가상 HTTPS 도메인(예: `https://sports-academy.local`)에 매핑 → WebView2가 안전한 원격 HTTPS로 인식.
자체 서명 인증서나 루프백 네트워킹 없이 카메라를 기동.

**✅ 확정 (2026-05-23)**: 가상 호스트 매핑(`SetVirtualHostNameToFolderMapping`)을 채택한다.
AssetServer secure-context 의존이 아니라, 명시적 `https://` 가상 도메인으로 카메라 권한을 확보한다.

> ⚠️ **남은 PoC(M-Spike)**: *접근법*은 확정됐으나, Wails **v2**에서 이 WebView2 네이티브 API를
> **어느 훅으로 주입**하는지는 코드로 확인 필요. v2는 WebView2 인스턴스에 직접 접근하는 공개 API가 제한적이라,
> 다음 순서로 PoC한다:
> 1. `options.App.OnStartup`/`OnDomReady` 시점에 WebView2 컨트롤러 핸들 확보 경로 탐색
>    (`go-webview2` 바인딩 또는 Wails 내부 노출 여부).
> 2. 핸들 확보 시 `CoreWebView2.SetVirtualHostNameToFolderMapping("sports-academy.local", <dist경로>, ALLOW)` 호출.
> 3. 불가 시 차선: cgo로 WebView2 COM 인터페이스 직접 호출, 또는 Wails v2 패치.
> 이 PoC가 **M1의 선행 조건**이다(프론트 추론 설계 전체가 카메라 기동에 의존).

권한 사전 점검: 최초 실행 시 Go가 윈도우 카메라 접근 권한 상태를 점검하고, 차단 시 네이티브 안내 표시.

### 3.2 프레임 병목 회피 — 프론트엔드 단독 추론

| 방식 | 프레임당 비용 | 채택 |
|---|---|---|
| 프레임을 Go로 전송 후 GoCV/ONNX 추론 | base64 직렬화 + IPC 마샬링 ≈ 수백 ms | ❌ |
| **WebView 내 WASM 추론** | 추론 ~30ms + IPC 0 (키포인트 배열만 비교) | ✅ |

→ MediaPipe `PoseLandmarker` **WASM 모듈을 앱 패키지에 임베딩**(CDN 미사용)하여 오프라인 구동.

## 4. 동작 비교 엔진 (3단계)

### 4.1 정규화 (스케일·위치 불변)

1. 골반 중심 `x_hip_midpoint`를 원점으로 평행이동: `x'_i = x_i − x_hip_midpoint`
2. 전체 관절 벡터 `V'`를 L2 노름으로 나눠 유닛 벡터화: `V_norm = V' / ‖V'‖₂`

→ 카메라 거리·체형에 무관한 정규 자세 확보.

### 4.2 관절 각도 정적 검증

관절 중심 `b`에서 뼈대 벡터 `u = a−b`, `v = c−b`가 이루는 각:

```
θ = | atan2(c_y−b_y, c_x−b_x) − atan2(a_y−b_y, a_x−b_x) |
θ_deg = θ × (180/π)
```

예: 스쿼트 하강 시 양 무릎 각도 ≤ 100° 여부로 세부 미션 통과 판정.

### 4.3 시퀀스 매칭 — S-WFDTW

운동은 시간축 프레임 흐름으로 평가. 학생별 속도차를 보정하기 위해
**Segmental Weighted Fast DTW** 도입 — 탐색 윈도우 제약 + 관절 가중치.

- 가중치 예(스쿼트 하강): `w_knee = 1.5`, `w_hip = 1.5`, `w_wrist = 0.5`
- 누적 비용 점화식:
  ```
  D(i,j) = d(x_i, y_j) + min{ D(i−1,j), D(i,j−1), D(i−1,j−1) }
  ```
- **조기 단락(Early Termination)**: `D(i,j) > h(=20)` 초과 시 즉시 중단 → 연산 절약.

> 참고 수치(원문 인용): BlazePose + KNN + S-WFDTW 결합 모델이 평균 98.33%~최대 100% 인식 정확도,
> 전체 연산 0.29초 내. **출처 미상 — 본 프로젝트 측정값 아님.** 목표치 참고용으로만 사용.

## 5. UI / UX

좌우 균등 분할 레이아웃. 색상·간격은 루트 [`../../DESIGN.md`](../../DESIGN.md) 토큰을 따른다.

```
+-----------------------------------------------------------------+
| 메뉴바: 스쿼트 학습 모드                            점수: 85점   |
+----------------------------------+------------------------------+
| 좌: 표준 가이드 비디오           | 우: 실시간 학생 웹캠 뷰      |
|  · AI Hub 기반 가이드 렌더링     |  · 실시간 웹캠 스트림(미러)  |

|         단계: 3 / 5              |         정합율: 89%          |
```

  → 위 ✅/❌ 등은 *문서용*이며 제품 UI에는 쓰지 않는다.

## 6. 이벤트 통신 파이프라인 (Wails v2)

성공 연출과 알림은 **전부 프론트에서** 처리하고, **기록만** Go로 보낸다.

```
[프론트] 5단계 도달 & 점수 ≥ 0.85
   ├─ (즉시, 0ms) Canvas Confetti + Web Audio 축하 연출
   ├─ Sonner 토스트: toast.success("스쿼트 성공! 92점")
   └─ EventsEmit("motion:success", { exercise:"squat", score:92 })
                        │  (Wails IPC, 이벤트 페이로드 수십 바이트)
                        ▼
[Go]  runtime.EventsOn(ctx, "motion:success", cb)
      └─ SQLite: 학생별 일일 누적 성공 기록 적재  (그게 전부)
```

> Go는 **알림을 발행하지 않는다.** 사용자 피드백(연출+토스트)은 100% WebView 내부에서 끝나고,
> Go의 책임은 영속화(SQLite)로 한정된다. 이로써 §0의 "Go는 비전 파이프라인에서 제외" 원칙이
> 알림 영역까지 확장된다.

### 6.1 Wails v2 API 정정

원문이 `Events.Emit` / `runtime.SendNotification` / "Wails v3 Notification API"로 기술한 부분을
**현재 채택된 Wails v2 기준으로 정정**한다:

| 원문 | Wails v2 실제 |
|---|---|
| `Events.Emit(...)` (JS) | `EventsEmit(name, payload)` (`@wailsapp/runtime`) |
| `EventsOn(ctx, ...)` (Go) | `runtime.EventsOn(ctx, name, cb)` — 시그니처 맞음 |
| `runtime.SendNotification` | **v2에 없음** — §6.3 참조 |

### 6.2 메모리/수명주기
- Go 리스너는 `OnShutdown`에서 해제. 장시간 세션 누수 방지를 위해 콜백 내 장기 참조 보관 금지.

### 6.3 ✅ 알림 — Sonner 인앱 토스트 (확정 2026-05-23)
네이티브 OS 알림은 **채택하지 않는다.** (원문이 전제한 "Wails v3 Notification API"는 v2에 없음 → 회피.)
모든 알림은 **[Sonner](https://sonner.emilkowal.ski/)** 기반 인앱 토스트로 처리한다.

- React 단독 의존성(`npm i sonner`), WebView 내부 렌더 → OS·Wails 버전 무관, 크로스플랫폼 안전.
- 성공: `toast.success("스쿼트 성공! 92점")`. 오류/안내(예: 카메라 권한 거절)도 동일 채널.
- **DESIGN.md 토스트 규칙 준수**: 우상단, 약 4s 자동 소멸, 작업을 막는 오류엔 토스트를 쓰지 않음
  (그런 경우 인라인 메시지). Sonner의 `position="top-right"`, `duration={4000}`로 매핑.
- `<Toaster />`는 앱 루트(`App.tsx`)에 1회 마운트.

> **Go 영향 없음**: 알림이 프론트 전용이 되면서 Go에 알림 코드/라이브러리(go-toast 등) 불필요.
> Go의 `motion:success` 리스너는 **SQLite 적재만** 수행.

## 7. 개발 로드맵 (PLAN 마일스톤에 매핑)

원문은 8주/Svelte 기준이었으나, **React/TS + 본 설계 마일스톤(M1~M6)**으로 재정렬:

| 마일스톤 | 핵심 작업 | 주요 리스크 → 완화 |
|---|---|---|
| **M-Spike (선행)** | `getUserMedia` 기동 PoC: **가상호스트 매핑** 주입 경로 확보 (Wails v2 WebView2 핸들 → `SetVirtualHostNameToFolderMapping`) | 접근법 확정·주입 훅만 미확정 → §3.1 3단계 PoC로 닫는다 |
| **M1** | WASM `PoseLandmarker`(Lite) 임베딩 로더 + 실시간 33 랜드마크 Canvas 오버레이 | WASM 초기 로드 지연 → 모델 앱 내 임베딩(CDN 미사용). 보급형 노트북 ≥15 FPS |
| **M2** | AI Hub → COCO-17 기준 벡터 추출 → `squat.json` + 정규화/각도 검증 | 33↔17 토폴로지 정합 오류 → 매핑 어댑터 + 3D 깊이 회전 보정 |
