> **상태**: Plan (PDCA - Plan 단계) · **일부 항목 Design에서 변경됨 ↓**
> **작성일**: 2026-05-23
> **대상 플랫폼**: Windows 데스크톱
> **기술 스택**: Go + Wails v2 + MediaPipe(~~Python 사이드카~~ → **WebView 내 WASM**, 아래 배너 참조)
> **데이터 출처**: [AI Hub](https://www.aihub.or.kr/index.do)

> ## ⚠️ 아키텍처 변경 (2026-05-23, Design 단계)
> 포즈 추정 방식이 **Python 사이드카 → WebView2 내부 WASM**(MediaPipe `PoseLandmarker`)으로 변경됨.
> 웹캠 프레임을 Go로 전송하는 IPC 병목(프레임당 수백 ms)을 피하기 위함. **Go는 비전 파이프라인에서 제외**되고
> SQLite 기록·알림만 담당. 이에 따라 **M0의 Python 사이드카(`app/sidecar*`)는 폐기(superseded)**됨.
> 상세·정정 사항은 [`../02-design/DESIGN.md`](../02-design/DESIGN.md) 참조. 아래 §3·§6·§7의 사이드카 기술은 **구버전**.

## 1. 프로젝트 개요

### 1.1 목적
학생이 웹캠 앞에서 화면에 제시된 **기본 운동 동작**을 따라 하고, 동작이 기준과 일치하면 **축하 이벤트**(애니메이션·효과음·점수)를 발생시켜 자기주도적으로 기본 동작을 익히도록 돕는 윈도우용 교육 앱.

### 1.2 핵심 사용자 흐름
```
운동 선택 → 화면에 시범 자세 제시 → 학생이 웹캠 앞에서 따라함
        → 실시간 포즈 추정 → 기준 동작과 비교(유사도 계산)
        → 임계값 이상 + 유지시간 충족 → 🎉 축하 이벤트 → 다음 동작
```

### 1.3 비목표 (Out of Scope, MVP 기준)
- 커스텀 동작 분류 모델 직접 학습 (※ AI Hub 데이터는 **기준 동작 정의용**으로만 사용)
- 다중 사용자 동시 인식 / 네트워크 멀티플레이
- 운동 처방·의료적 자세 교정 (재활 등 전문 영역)
- 모바일/웹 빌드 (Windows 단일 타깃)

## 2. 기술 가능성 검토 (Feasibility)

### 2.1 결론: **가능함 (High Confidence)**
선택한 조합(MediaPipe 사이드카 + 템플릿 매칭 + 소수 동작)은 모든 구성요소가 검증된 기술이며, ML 모델을 직접 학습하지 않으므로 GPU 없이도 MVP 구현이 현실적입니다.

### 2.2 구성요소별 검증

| 구성요소 | 검증 결과 | 근거 |
|---|---|---|
| **포즈 추정** | ✅ 검증됨 | MediaPipe Pose는 RGB 영상에서 33개 3D 랜드마크를 실시간 추출. CPU에서도 동작(경량 모델 `model_complexity=0`). Python 바인딩 성숙. |
| **기준 동작 데이터** | ✅ 존재 확인 | AI Hub에 '피트니스 자세 이미지'(70종 동작, 2D 200만 장), '사람 동작 영상', '3D 인체/자세' 데이터셋 실재. |
| **Go ↔ Python 통신** | ✅ 가능 | Wails엔 Tauri식 내장 sidecar는 없으나, Go `embed.FS`로 PyInstaller 실행파일 번들 → 런타임 추출 → 자식 프로세스 실행 패턴으로 구현 가능. |
| **축하 이벤트(UI)** | ✅ 용이 | Wails 프론트엔드(웹뷰)에서 애니메이션·효과음 처리. 표준 웹 기술. |
| **단일 exe 배포** | ⚠️ 조건부 | Python 런타임 동봉으로 설치 크기 증가(수십~수백 MB). 인스톨러로 해결. |

### 2.3 핵심 리스크와 완화책

| 리스크 | 영향 | 완화책 |
|---|---|---|
| Python 런타임 번들로 인한 배포 크기/복잡도 | 중 | PyInstaller `--onefile` + Inno Setup 인스톨러. 사이드카를 옵션으로 분리 가능하게 설계. |
| 저사양 노트북(GPU 없음) 성능 | 중 | `model_complexity=0` 경량 모델 기본값, 처리 해상도/FPS 동적 조절. **혼합 환경 대응**: 자동 성능 프로파일링 후 품질 단계 선택. |
| 조명·배경·카메라 각도 편차 | 중 | 각도 기반(관절 각도) 비교로 위치/스케일 불변성 확보. 캘리브레이션 단계 추가. |
| 사이드카 프로세스 비정상 종료 | 중 | Go 측 헬스체크·자동 재시작, IPC 타임아웃 처리. |
| AI Hub 데이터 라이선스/이용약관 | 낮~중 | 데이터는 기준 각도 추출용으로만 가공 사용. 약관 확인 후 출처 명시. |

## 3. 시스템 아키텍처

```
┌─────────────────────────────────────────────────────────┐
│  Wails 앱 (단일 Windows 실행파일)                          │
│                                                           │
│  ┌──────────────────┐         ┌────────────────────────┐ │
│  │  Frontend (WebView)│  IPC   │  Go Backend            │ │
│  │  - 운동 선택 UI    │◀──────▶│  - 세션 상태 관리       │ │
│  │  - 시범 자세 표시  │ Wails  │  - 동작 판정 로직       │ │
│  │  - 실시간 피드백   │ Bind   │  - 기준 템플릿 로딩     │ │
│  │  - 🎉 축하 이벤트   │        │  - 사이드카 수명주기    │ │
│  └──────────────────┘         └───────────┬────────────┘ │
│                                            │ stdio/socket │
│                              ┌─────────────▼────────────┐ │
│                              │ Python 사이드카 (번들)    │ │
│                              │ - OpenCV 웹캠 캡처        │ │
│                              │ - MediaPipe Pose 추정     │ │
│                              │ - 33 랜드마크 → JSON 출력 │ │
│                              └──────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
                                            ▲
                          (오프라인 사전 가공)│
                              ┌─────────────┴────────────┐
                              │ AI Hub 데이터 → 기준 각도  │
                              │ 추출 스크립트 (개발 단계만) │
                              │ → exercises/*.json 템플릿  │
                              └──────────────────────────┘
```

### 3.1 데이터 흐름
1. **오프라인(개발 시)**: AI Hub 자세 데이터에서 각 운동의 핵심 관절 각도 범위를 추출 → `exercises/*.json` 기준 템플릿 생성.
2. **런타임**: 사이드카가 웹캠 프레임마다 33개 랜드마크를 추출해 Go로 전송.
3. Go가 현재 포즈의 관절 각도를 계산하고 기준 템플릿과 비교 → 유사도 점수 산출.
4. 점수가 임계값 이상으로 N초 유지되면 프론트엔드에 `match` 이벤트 발행 → 축하 연출.

### 3.2 IPC 방식 (1차안)
- **stdin/stdout JSON Lines**: 사이드카가 프레임당 한 줄 JSON으로 랜드마크 출력. 단순·디버깅 용이.
- 성능 이슈 시 → 로컬 TCP/Unix 소켓 또는 공유 메모리로 승격.

## 4. 동작 판정 로직 (템플릿 매칭)

### 4.1 기준 동작 표현
각 운동을 **핵심 관절 각도들의 목표값 + 허용 오차**로 정의 (위치/카메라 거리 불변).

```jsonc
// exercises/squat.json (예시 스키마)
{
  "id": "squat",
  "name": "스쿼트",
  "phases": [
    {
      "name": "하강",
      "joints": {
        "left_knee":  { "target": 90,  "tolerance": 15 },
        "right_knee": { "target": 90,  "tolerance": 15 },
        "left_hip":   { "target": 80,  "tolerance": 20 }
      },
      "hold_ms": 800
    }
  ]
}
```

### 4.2 유사도 산출
- 관절별 `각도 오차 → 점수(0~1)` 매핑 후 가중 평균.
- 양측 관절은 좌우 모두 평가(대칭성).
- 신뢰도(landmark visibility) 낮은 관절은 가중치 감소.

### 4.3 MVP 대상 동작 (소수 핵심 — 3~5개)
| ID | 동작 | 핵심 판정 관절 |
|---|---|---|
| `squat` | 스쿼트 | 무릎/엉덩이 각도 |
| `arm_raise` | 양팔 벌려 올리기(만세) | 어깨/팔꿈치 각도 |
| `side_stretch` | 옆구리 늘리기 | 척추 측면 기울기 |
| `lunge` | 런지 | 앞무릎/뒷다리 각도 |
| `t_pose` | T자 서기(캘리브레이션 겸용) | 어깨/팔 수평 |

---

## 5. 축하 이벤트 (게이미피케이션)

- **시각**: 컨페티 애니메이션, 동작별 진행도 게이지, 별/배지 획득 연출.
- **청각**: 성공 효과음(설정에서 음소거 가능 — 교실 환경 고려).
- **피드백**: 동작 직전·직후 "조금 더 무릎을 굽혀보세요" 같은 방향 힌트(각도 오차 부호 기반).
- **누적**: 세션별 완료 동작 수·연속 성공 콤보 표시(로컬 저장).

> 마일스톤도 WASM 전환에 맞춰 재정렬됨 — 최신 정의는 [DESIGN.md §7](../02-design/DESIGN.md) 우선.

| 단계 | 산출물 | 검증 기준 |
|---|---|---|
| ~~**M0. 기술 스파이크**~~ | ~~Wails 빈 앱 + Python 사이드카 1프레임 왕복~~ | ✅ **완료(2026-05-23)** — 단, 사이드카 방식은 폐기. 빌드 체인 검증 가치만 유효 |
| **M-Spike. getUserMedia PoC** | WebView2 보안 컨텍스트에서 웹캠 기동 (가상호스트 매핑 vs AssetServer) | 카메라 스트림 권한 획득 성공 |
| **M1. 포즈 파이프라인** | 웹캠 + **WASM PoseLandmarker** 실시간 33 랜드마크 Canvas 오버레이 | 보급형 노트북에서 ≥15 FPS |
| **M2. 기준 템플릿** | AI Hub 데이터 → `squat.json` 1종 추출 + 판정 로직 | 스쿼트 1동작 매칭/점수 동작 |
| **M3. 축하 이벤트** | 매칭 시 컨페티+효과음 + 동작 전환 | 전체 1동작 풀 루프 완성 |
| **M4. 동작 확장** | 핵심 동작 3~5개 + 운동 선택 화면 | 모든 MVP 동작 통과 |
| **M5. 성능/배포** | 성능 자동 프로파일링 + Inno Setup 인스톨러 | 혼합 환경 2종에서 설치·실행 |
| **M6. QA/마감** | 캘리브레이션, 설정(음소거/난이도), 다듬기 | 학생 파일럿 테스트 |

## 7. 기술 스택 상세

| 영역 | 선택 | 비고 |
|---|---|---|
| 데스크톱 셸 | Wails v2 | Go 백엔드 + 웹뷰 프론트 |
| 백엔드 언어 | Go 1.22+ | 세션·판정·사이드카 관리 |
| 프론트엔드 | **React/TS** (M0에서 확정) | 가장 성숙한 Wails 템플릿 + 풍부한 애니메이션 생태계(컨페티 등) |
| 포즈 추정 | **MediaPipe Tasks `PoseLandmarker` (WASM, Lite)** | ~~Python 사이드카~~ → WebView2 내부 실행. Python 의존성 제거 |
| ~~사이드카 패키징~~ | ~~PyInstaller `--onefile`~~ | **불필요** — WASM 모델을 앱 자산에 임베딩 |
| 인스톨러 | Inno Setup (또는 NSIS) | Windows 단일 설치파일 |
| 데이터 가공 | Python 스크립트(개발 전용) | AI Hub → 기준 각도 JSON |

## 8. 다음 단계 결정 필요 항목 (Design 단계에서 확정)
1. ~~**프론트엔드 프레임워크**: React vs Svelte~~ → **React/TS 확정** (2026-05-23, M0). `wails init -t react-ts`.
2. ~~**IPC 세부 프로토콜**: stdio JSON Lines~~ → **무의미해짐**. WASM 전환으로 프레임 IPC 자체가 사라짐.
   남은 IPC는 `EventsEmit`/`EventsOn`로 주고받는 성공 이벤트뿐. [DESIGN.md §6](../02-design/DESIGN.md) 참조.

4. **MVP 동작 5개 최종 확정** 및 각 동작의 판정 관절/임계값 초안.
